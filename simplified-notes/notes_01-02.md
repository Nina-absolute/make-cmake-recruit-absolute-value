# Make & CMake：Task 1–2 笔记

## Task 1：C 程序的构建阶段

以 `hello.c` 为例，常用命令如下：

```bash
gcc -E hello.c -o hello.i
gcc -S hello.i -o hello.s
gcc -c hello.s -o hello.o
gcc hello.o -o hello
```

- 预处理：展开 `#include`、宏和条件编译，生成 `.i`。
- 编译：检查 C 代码并生成汇编代码 `.s`。
- 汇编：把汇编转换为机器码，生成还未完成链接的目标文件 `.o`。
- 链接：解析外部符号、合并目标文件和所需库，生成可执行文件。

`-E` 只预处理，`-S` 停在汇编阶段，`-c` 只生成目标文件而不链接，`-o` 指定输出文件。没有这些“停止”选项时，`gcc` 通常会继续直到生成可执行文件。

## Task 2：Makefile 的规则与增量构建

Makefile 的基本形式：

```make
target: prerequisites
	recipe
```

Make 根据目标与依赖文件的时间戳判断哪些规则需要执行。源文件或头文件比对应目标更新时，相关目标文件会重新编译；链接目标在任意输入的 `.o` 文件更新后重新链接。这比逐条执行全部 `gcc` 命令更高效。

本题中的变量和自动变量：

- `CC`：C 编译器命令，本题为 `gcc`。
- `CFLAGS`：传给 C 编译步骤的选项，例如 `-Wall -Wextra -Iinclude`。
- `$@`：当前规则的目标文件名。
- `$<`：第一个依赖，适合单个源文件的编译规则。
- `$^`：所有依赖，适合链接多个目标文件。

`-Wall` 和 `-Wextra` 开启常用警告；`-Iinclude` 增加头文件搜索目录。`.PHONY: clean` 表明 `clean` 是动作而不是要生成的文件，避免同名文件存在时 Make 误判它已完成。

本题直接列出头文件依赖已经足够。真实项目中还会使用编译器生成依赖文件（如 `-MMD -MP`），避免手工维护大量头文件依赖。
