### 一、分析 `.i` 文件（预处理后）
**生成命令**：`gcc -E hello.c -o hello.i`
**文件性质**：**纯文本 C 代码**（但极其庞大）

**具体内容特点**：
1. **头文件展开**：
   你写的 `#include <stdio.h>` 那一行消失了，取而代之的是 `stdio.h` 文件里的几千行代码（包括 `printf` 的声明、各种宏、结构体定义）。
2. **宏替换**：
   代码里的 `MAX` 全部被替换成了 `100`。
3. **注释删除**：
   你写的 `// 打印问候语` 完全消失。
4. **行控制**：
   会插入类似 `# 1 "hello.c"`、`# 1 "/usr/include/stdio.h"` 的标记，告诉编译器接下来的代码原本属于哪个文件哪一行，便于报错时定位。
5. **条件编译处理**：
   `#ifdef` 等根据规则进行代码删减。

**大白话总结**：`.i` 文件就是**把所有的“拼图碎片”（头文件、宏）全部拼好，删掉注释，只留下编译器真正需要翻译的纯粹的 C 语言代码**。

---

### 二、分析 `.s` 文件（汇编代码）
**生成命令**：`gcc -S hello.i -o hello.s`
**文件性质**：**文本文件**（人类可读，但需要懂汇编）

**具体内容特点**：
打开 `hello.s`，你会看到类似这样的代码（以 x86-64 架构为例）：
```assembly
	.file	"hello.c"
	.text
	.section	.rodata
.LC0:
	.string	"Hello, %d\n"
	.text
	.globl	main
	.type	main, @function
main:
	pushq	%rbp
	movq	%rsp, %rbp
	movl	$100, %esi       # 注意：MAX 变成了 100
	leaq	.LC0(%rip), %rdi # 加载字符串地址
	movl	$0, %eax
	call	printf@PLT       # 调用 printf 函数
	movl	$0, %eax
	popq	%rbp
	ret
```

**具体内容拆解**：
1. **`.file`**：记录原始文件名。
2. **`.section .rodata`**：只读数据段，存放字符串常量 `"Hello, %d\n"`。
3. **`.text`**：代码段，存放真正的指令。
4. **`.globl main`**：声明 `main` 是全局符号，链接器需要用到。
5. **指令部分**：`pushq`、`movq`、`call` 等就是 CPU 实际要执行的汇编指令。
6. **优化体现**：如果你加了 `-O2`，这里会看到指令被大幅精简，甚至 `printf` 可能被替换成 `puts`。

**大白话总结**：`.s` 文件是**把 C 语言翻译成 CPU 能看懂的“外语草稿”**，里面全是寄存器和内存地址的操作。

### 三、分析 `.o` 文件（目标文件）
**生成命令**：`gcc -c hello.s -o hello.o`
**文件性质**：**二进制文件**（ELF 格式，用文本编辑器打开是乱码）

**具体内容特点**（需要使用 `readelf`、`objdump`、`nm` 等工具查看）：
一个 `.o` 文件内部被划分成了多个“节区”（Section），核心包含：

1. **机器码（`.text` 节）**：
   汇编指令被翻译成了 0 和 1 组成的机器码。用 `objdump -d hello.o` 可以看到：
   ```text
   0000000000000000 <main>:
      0:	55                   	push   %rbp
      1:	48 89 e5             	mov    %rsp,%rbp
      4:	be 64 00 00 00       	mov    $0x64,%esi  # 0x64 就是 100
      9:	48 8d 3d 00 00 00 00 	lea    0x0(%rip),%rdi # 重定位目标
     10:	b8 00 00 00 00       	mov    $0x0,%eax
     15:	e8 00 00 00 00       	call   1a <main+0x1a> # 重定位目标
   ```
   注意：`call` 后面的地址是 `00 00 00 00`，因为**不知道 `printf` 在最终程序里的地址**，要等链接器来填。

2. **符号表（`.symtab` 节）**：
   用 `nm hello.o` 查看：
   ```text
   0000000000000000 T main
                    U printf
   ```
   - `T main`：表示 `main` 函数在这个文件里**已定义**（Text 段）。
   - `U printf`：表示 `printf` 是**未定义**的（Undefined），需要链接器去标准库 `libc` 里找。

3. **重定位表（`.rela.text` 节）**：
   告诉链接器：**代码里哪些地方需要修改地址**。比如上面 `call printf` 的地址占位符、字符串常量的地址，都需要在链接时修正。

4. **节区头表（Section Header Table）**：
   记录了这个 `.o` 文件里有哪些节区、每个节区的偏移量、大小等。

**大白话总结**：`.o` 文件是**把汇编代码翻译成了二进制机器码，但打了“补丁”**。它记录了“我用到了一些外部函数（比如 printf），但我不知道它们在哪，请链接器大哥帮我填上地址”。

### 四、横向对比总结

| 对比项 | `.i` 文件 | `.s` 文件 | `.o` 文件 |
|---|---|---|---|
| **文件类型** | 文本 | 文本 | 二进制（ELF） |
| **核心内容** | 展开后的 C 代码 | 汇编指令 | 机器码 + 符号表 + 重定位表 |
| **能否直接运行** | 否 | 否 | 否 |
| **查看工具** | `cat`, `less` | `cat`, `less` | `objdump`, `readelf`, `nm` |
| **大小** | 极大（几万行） | 中等（几百行） | 较小（几 KB） |
| **包含注释吗** | 否 | 否 | 否 |
| **包含变量名吗** | 是 | 部分（符号） | 部分（符号表） |

## 2. Makefile 中常见的自动变量

| 自动变量 | 英文全称 | 中文释义 | 展开结果 | 小白大白话 | 常见用途 |
| --- | --- | --- | --- | --- | --- |
| `$@` | `Dollar At` | 当前目标 | `target` | 当前要生成的文件名 | 指定输出文件 |
| `$<` | `Dollar Less` | 第一个依赖 | 第一个 `prerequisites` | 第一个原材料 | 编译单个源文件 |
| `$^` | `Dollar Caret` | 所有依赖 | 所有 `prerequisites`（去重） | 所有原材料 | 链接所有 `.o` |
| `$+` | `Dollar Plus` | 所有依赖（不去重） | 所有 `prerequisites`（保留重复） | 所有原材料，重复也列 | 特殊场景 |
| `$?` | `Dollar Question` | 比目标新的依赖 | 更新的 `prerequisites` | 新鲜材料 | 只处理变化 |
| `$*` | `Dollar Star` | 目标主干名 | `target` 去掉后缀 | 文件名主干 | 模式规则 |
